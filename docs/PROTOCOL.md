# KeyboardKu UDP protocol v2

Single UDP port **47800** for discovery, pairing, and data. All integers are **little-endian**.
Every packet starts with an 8-byte header:

| off | type | field       | notes |
|----:|------|-------------|-------|
| 0   | u8   | magic       | `0xA8` |
| 1   | u8   | type        | see below |
| 2   | u16  | sessionId   | 0 before WELCOME |
| 4   | u32  | seq         | per-direction counter; also the AEAD nonce |

## Handshake (plaintext, never carries secrets)

| type | name     | dir | size | body after header |
|------|----------|-----|-----:|-------------------|
| 0x20 | DISCOVER | P→S | 16   | 8 zero bytes. Sent to every interface's subnet broadcast, 255.255.255.255, and a manual IP. |
| 0x21 | OFFER    | S→P | 52   | `nonceS[8]`, `ver u16 (=2)`, `flags u16 (bit0 = pairing allowed, bit1 = no code needed: server started with --no-auth, phone uses "000000")`, `name[32]` UTF-8 zero-padded (COMPUTERNAME) |
| 0x10 | HELLO    | P→S | 48   | `nonceS[8]` (echoed), `nonceC[8]`, `peerId[8]`, `mac[16]` = HMAC-SHA256(PSK, "hello" ‖ nonceS ‖ nonceC ‖ peerId)[0..16] |
| 0x13 | PAIR     | P→S | 48   | `nonceS[8]` (echoed), `nonceC[8]`, `peerId[8]`, `mac[16]` = HMAC-SHA256(K0, "pair" ‖ nonceS ‖ nonceC ‖ peerId)[0..16] where **K0 = HKDF-SHA256(ikm = 6 ASCII digits, salt = nonceS ‖ nonceC, info = "keyboardku-pair")** |
| 0x11 | WELCOME  | S→P | 32   | encrypted data packet (see below) with payload `ver u16, flags u16, screenW u16, screenH u16` (host virtual-desktop size, for air-mouse px/deg) |
| 0x12 | REJECT   | S→P | 16   | `reason u8` (1 unknown peer → send PAIR, 2 bad mac / wrong code, 3 rate limited, 4 version, 5 pairing disabled), `retryAfterMs u16`, pad |

After a successful PAIR both sides store **PSK = HKDF-SHA256(ikm = K0, salt = "", info = "keyboardku-psk")** under `peerId`
(phone: SharedPreferences; server: `%APPDATA%\KeyboardKu\peers.bin`, records of 8 + 32 bytes). Later sessions use HELLO only.

Session keys (both after HELLO or PAIR succeed):
- `keyC2S = HKDF-SHA256(ikm = PSK, salt = nonceS ‖ nonceC, info = "keyboardku-c2s")`
- `keyS2C = HKDF-SHA256(ikm = PSK, salt = nonceS ‖ nonceC, info = "keyboardku-s2c")`
- `sessionId` = random non-zero u16 chosen by the server, carried in WELCOME's header.

Server nonce handling: each DISCOVER gets a fresh `nonceS`; the last 4 are remembered for 10 s. Rate limit for PAIR: after 3 failures, one attempt per 2 s; after 10 failures the code is rotated (printed again).

## Data packets (32 bytes, encrypted)

`header[8]` ‖ `ciphertext[8]` ‖ `tag[16]` — **ChaCha20-Poly1305** (RFC 8439), AAD = header, nonce(12) = `sessionId as u32 LE` ‖ `seq as u64 LE`.
Server keeps a 64-packet replay window around the highest seq; duplicates and packets older than the window are dropped.
Packets with a wrong length, magic, sessionId, or tag are dropped silently.

Plaintext payload (8 bytes) by type:

| type | name        | dir | payload | semantics |
|------|-------------|-----|---------|-----------|
| 0x01 | MOUSE       | P→S | `i32 cumX, i32 cumY` | **cumulative** pixel counters since session start. Server applies `cum - lastApplied`; only if seq > last MOUSE seq (older ones dropped). A lost packet is healed by the next one. |
| 0x02 | SCROLL      | P→S | `i32 cumV, i32 cumH` | cumulative, units of 1/120 notch (+V = away from user). Same rules as MOUSE. |
| 0x03 | BUTTONS     | P→S | `u8 mask` (bit0 L, bit1 R, bit2 M, bit3 X1, bit4 X2), pad | **full state**; sent 3× 2 ms apart on every change; idempotent. |
| 0x04 | KEYS        | P→S | `u8 mods` (HID bits: 0x01 LCtrl 0x02 LShift 0x04 LAlt 0x08 LGui 0x10 RCtrl 0x20 RShift 0x40 RAlt 0x80 RGui), `u8 key[6]` HID usages, pad | **full state** like a HID keyboard report; sent 3×; server diffs against held state. Key repeat is generated by the server. |
| 0x05 | UNICODE     | P→S | `u8 count (1..3)`, `u8 textSeq`, `u16 cu[3]` UTF-16 units | sent 2×; server applies only if `textSeq` is newer (wrap-aware) than the last applied. Surrogate pairs are kept in one packet. |
| 0x06 | CONSUMER    | P→S | `u16 usage` (0 = released), pad | full state of the single held consumer-control usage (0xE9 Vol+, 0xEA Vol-, 0xE2 Mute, 0xCD Play/Pause, 0xB5 Next, 0xB6 Prev); sent 3×. |
| 0x07 | HEARTBEAT   | P→S | `u32 phoneMs`, `u8 held` (1 if any key/button is down or a drag is active), pad | 0.5 Hz idle, 10 Hz while `held`. |
| 0x08 | RELEASE_ALL | P→S | zeros | server releases every key/button/consumer it holds. |
| 0x22 | PONG        | S→P | `u32 echoPhoneMs, u32 serverUptimeMs` | reply to HEARTBEAT (phone computes RTT). |

Server watchdog: `held = 1` and no packet for 500 ms → release all; no packet at all for 6 s → release all (session stays valid).
Phone: no PONG for 3 s → RECONNECTING (HELLO every 1 s with the known nonces; after 10 s DISCOVER again).
Phone sends RELEASE_ALL + BUTTONS(0) + KEYS(0) on pause/screen-off, and as the first packets after (re)connecting.
